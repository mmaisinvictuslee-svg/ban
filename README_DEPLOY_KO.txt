VillageON · 지역 관리자·상인용 시뮬레이터 배포 및 업데이트
=====================================

1. 배포 파일 배치

villageon_deploy.zip을 압축 해제합니다.
이 ZIP은 app.py와 requirements.txt가 맨 바깥(루트)에 있습니다.
다음 파일들을 GitHub 저장소에 올립니다. ZIP 자체를 올리는 방식으로 앱이 실행되지는 않습니다.

app.py
requirements.txt
.streamlit/config.toml
.gitignore
README_DEPLOY_KO.txt
README_KO.txt

이미 배포했다면 Streamlit의 Main file path와 같은 경로에 있는 app.py와 새 requirements.txt를 교체하고 Commit합니다.
이전 app.py에 개인 API 키를 직접 넣었다면 교체 전에 본인의 키를 별도로 보관하세요.
다운로드한 새 코드의 키 입력칸은 빈칸이며 이전 값이 자동 복사되지는 않습니다.
공개 GitHub 저장소에는 실제 키를 넣은 파일을 올리지 않습니다.


2. API 키 자동 사용

공개 배포의 app.py 맨 위는 다음처럼 비워 둡니다.

ADMIN_API_KEY = ""
KAKAO_REST_API_KEY = ""

대신 Streamlit 앱의 Settings → Secrets에 아래 형식으로 본인의 실제 키를 등록합니다.
아래 따옴표 안 문구는 입력 위치 설명입니다. 실제 키로 바꾸되 양쪽 따옴표를 유지합니다.

ADMIN_API_KEY = "본인의 행정안전부 Decoding 키 전체"
KAKAO_REST_API_KEY = "본인의 카카오 REST API 키 전체"

등록 후 앱을 다시 실행하면 서버가 자동으로 읽습니다.
사이트 방문자나 휴대폰 접속자에게는 API 키 입력창이 나타나지 않습니다.
설정이 있다는 상태와 실제 인증 성공은 다르므로 지역 목록과 장소 검색 결과를 확인하세요.

기존 적용 순서는 유지합니다.
코드 직접 값 → Streamlit Secrets → 환경변수 → 로컬 도우미 JSON.
코드에 값을 채워 놓으면 Secrets보다 먼저 적용되므로 공개 배포에서는 빈칸으로 둡니다.
환경변수의 이름도 ADMIN_API_KEY와 KAKAO_REST_API_KEY입니다.
프로젝트의 Secrets는 사용자 공통 Secrets의 같은 이름보다 우선합니다.
.env 파일을 자동으로 읽는 기능은 없습니다.

실제 키가 있는 secrets.toml, villageon_keys.json, .env와 .venv 폴더는 저장소에 올리지 않습니다.
로컬 전용 설정 도우미는 Cloud 배포에 필요하지 않습니다.


3. Streamlit Community Cloud 연결

https://share.streamlit.io/ 에서 실제 GitHub Repository와 Branch를 선택해 앱을 생성합니다.
이 배포 ZIP의 구조를 그대로 올렸다면 Main file path는 app.py입니다.
하위 폴더에 앱을 두었다면 villageon/app.py처럼 /를 사용해 전체 경로를 지정합니다.
대소문자와 파일 이름을 맞춥니다. 개발 검사에는 Python 3.12를 사용했습니다.
패키지 설치 후 Streamlit이 제공하는 앱 주소로 접속하고 그 주소를 공유합니다.
GitHub Pages는 이 Python 서버 앱을 실행하지 않으므로 Pages 주소를 사용하지 않습니다.


4. 이번 버전의 화면

메뉴는 콘텐츠 탐색 / 지역 소비 시뮬레이터 / AI 추천 / 예산 여행 코스의 네 개입니다.
지역 소비 시뮬레이터는 지역 관리자·상인회와 개별 상인을 위한 두 가지 계산으로 구성했습니다.
지역 브리핑 제거, 콘텐츠의 전체 분류 제거, 큰 버튼, AI의 동일 숙소 일정은 유지합니다.
시뮬레이터의 그래프와 지출 편집표, Plotly 의존성은 제거했습니다. 기존 여행 지도는 계속 표시합니다.
메뉴, 콘텐츠 선택, 검색·계산·다운로드 버튼의 글씨와 누를 수 있는 영역을 키웠습니다.

콘텐츠 탐색:
'전체'를 제거하고 맛집·카페·관광지·숙박·학교·공원·문화·체험 중에서 고릅니다.
검색 결과는 카카오 정확도순 기준 최대 45곳이며 수 옆에 정렬 기준을 표시합니다.
거리순을 선택한 결과는 거리순이라고 표시합니다.
45는 검색 목록의 수집 상한이지 지역 전체 시설 수가 아닙니다.
검색 결과가 적거나 중복·부분 오류가 있으면 실제 확인한 수만 표시합니다.
카카오 Local API가 별점과 평가 수를 제공하지 않으므로 별점순 정렬은 지원하지 않습니다.

지역 소비 시뮬레이터:
[지역 전체 소비 효과]와 [우리 가게 예상 매출] 중에서 고릅니다.
선택 지역을 기준으로 분석 기간 이름과 그 기간의 추가 방문객 수를 입력합니다.
이 인원은 여행 일행이 아니라 지역에 더 방문할 것으로 가정한 사람 수입니다.

지역 전체 계산은 1인 당일 지출과 전체 지출 중 선택 지역 안에서 쓸 비율을 기본 입력으로 둡니다.
기본 숙박 비율은 0%입니다. 1,000명 × 50,000원 × 지역 내 80%이면 예상 지역 소비액은 40,000,000원입니다.
숙박 가정은 접힌 영역에서 조정합니다. 숙박객 일일 지출은 평균 숙박일+1일, 숙박비는 숙박 횟수만 반영합니다.
지역 내 비율은 일반 지출과 숙박비에 동일하게 적용하며 선택 지역에서 이용·결제할 몫을 뜻합니다.
숙박 여행의 모든 숙소가 선택 지역 안에 있다고 확정하거나 순이익률로 해석하지 않습니다.
식비·카페·체험·현지 교통·쇼핑의 나눔 비율은 합계 100%로 조정할 수 있으며 숙박비는 별도 항목입니다.
큰 숫자와 업종별 읽기 전용 표로 결과를 보여 줍니다. 그래프와 지출 편집표는 없습니다.

우리 가게 계산은 가게 이름(선택), 추가 방문객 중 구매할 비율과 고객 1명의 평균 구매 금액을 입력합니다.
1,000명 × 구매 비율 3% = 추가 고객 30명, 30명 × 20,000원 = 예상 추가 매출 600,000원입니다.
고객 수를 0.5명 이상 올려 정수로 반올림한 뒤 매출을 계산하며 한 사람당 한 번 구매한다고 가정합니다.
매출은 비용을 빼기 전 금액입니다. 지역 소비액을 가게 수로 균등 배분하거나 두 계산 결과를 합산하지 않습니다.

계산 버튼을 눌러 결과를 갱신합니다. 마지막 제출 조건을 표시하고 지역·계산 대상에 맞는 결과만 보여 줍니다.
상세 계산, 방문객 80%·100%·120% 가정 비교와 CSV는 접힌 영역에서 확인합니다.
분석 기간 이름을 바꿔도 방문객 수를 자동으로 곱하지 않습니다.
모든 기본값은 예시입니다. 실제 매출·공식 통계·실제 가격·AI 예측이나 경제 파급 효과를 측정한 값이 아닙니다.

AI 추천:
관심사에 맞는 분야별 후보를 최대 45곳 보여 주고 목록 옆에 카카오 검색 정렬 기준을 표시합니다.
후보 목록은 검색 순서이고 시간표와 지도는 방문 순서입니다.
숙박 여행은 한 숙소를 골라 여행 기간 내내 같은 곳을 이용합니다.
2박 3일이면 1일차·2일차 밤에 같은 숙소에서 자고 3일차 아침 체크아웃합니다.
마지막 날 밤의 숙박은 추가하지 않습니다. 당일치기에는 숙박이 없습니다.
숙소가 검색되지 않으면 직접 정하도록 안내합니다.
실제 연박 예약 가능 여부와 요금, 체크인/체크아웃 시각은 확인해야 합니다.
날짜별 지도는 실제 좌표를 방문 순서대로 직선 연결한 개요이며 도로 길찾기 경로가 아닙니다.


5. 로컬 재실행과 배포 업데이트 확인

기존 Windows 폴더를 계속 사용하고 패키지가 이미 설치되어 있다면 다음 두 줄로 다시 실행합니다.

cd "C:\Users\user\Desktop\0723"
.\.venv\Scripts\python.exe -m streamlit run .\app.py

터미널을 닫았다가 다시 열었다고 재설치할 필요는 없습니다.
새 환경이거나 패키지 누락 오류가 있을 때만 같은 Python으로 설치합니다.

.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt

코드를 직접 수정해 키를 넣는 개인 PC에서는 키 앞뒤 큰따옴표를 모두 유지합니다.
unterminated string literal 오류는 닫는 따옴표가 빠졌거나 문자열을 실제 줄바꿈한 경우를 확인합니다.
오류를 공유할 때 실제 키는 가려 주세요.

배포 화면이 바뀌지 않았다면:
- 저장소의 Main file path와 실제 교체한 파일 위치가 같은지 확인합니다.
- Commit과 서버 업데이트 완료를 확인한 뒤 앱을 다시 엽니다.
- 다운로드만으로 이미 배포한 사이트의 코드가 바뀌지는 않습니다.

그 밖의 오류:
- File not found: 앱 파일 경로와 대소문자 확인.
- No module named streamlit: requirements.txt의 위치와 설치 로그 확인.
- korea_administrative_district: 이전 코드가 실행 중인지 확인. 이번 코드는 해당 모듈을 사용하지 않습니다.
- 행정안전부 오류: 활용 신청 승인, Decoding 키, 호출 한도와 연결 확인.
- 카카오 오류: REST API 키, Local API 권한, 호출 한도와 연결 확인.

그래프를 제거하면서 requirements.txt의 Plotly 의존성도 제거했습니다.
기존 환경에 Plotly가 설치되어 있어도 직접 삭제할 필요는 없습니다.
검증 범위는 문법 및 모의 응답 기반 기능 검사입니다.
실제 사용자의 유효 키 인증, 실제 Cloud 배포, Windows 또는 휴대폰 직접 조작 검사는 하지 않았습니다.
