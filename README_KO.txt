VillageON · 지역 관리자와 상인을 위한 소비 시뮬레이터
================================================

1. 이미 사용 중이라면 이렇게 교체하세요

1) 기존 app.py에 API 키를 직접 넣었다면, 파일을 교체하기 전에 본인의 두 키를 개인적으로 보관합니다.
   새 파일의 키 입력칸은 비어 있습니다. 기존 개인 키는 새 코드에 자동으로 옮겨지지 않습니다.
2) 실행 중인 터미널에서 Ctrl+C를 눌러 이전 앱을 종료합니다.
3) 기존 코드를 백업한 뒤 새 app.py와 requirements.txt로 교체합니다. 실행 도우미도 갱신하려면 ZIP의 파일들을 함께 복사합니다.
4) 새 app.py 맨 위의 두 빈 문자열에 키를 다시 넣고 Ctrl+S로 저장합니다.
   이미 Secrets, 환경변수 또는 설정 도우미를 사용했다면 코드의 두 값은 빈칸으로 두면 됩니다.
5) VS Code의 [터미널 → 새 터미널]에서 아래 명령을 한 줄씩 실행합니다.

cd "C:\Users\user\Desktop\0723"
.\.venv\Scripts\python.exe -m streamlit run .\app.py

다른 폴더에 앱을 두었다면 cd 경로를 app.py가 실제로 있는 폴더로 바꾸세요.
PS C:\...> 같은 터미널 프롬프트 문자는 입력하지 않습니다.
이미 필요한 패키지가 설치되어 있으면 위 두 줄만 사용하면 됩니다.
터미널을 삭제하거나 VS Code를 껐다 켰다고 패키지를 다시 설치할 필요는 없습니다.


2. 처음 설치하는 경우

가장 쉬운 방법:
- villageon.zip을 [모두 압축 풀기]로 해제합니다.
- 안의 villageon 폴더에서 app.py, requirements.txt, run_windows.bat가 함께 있는지 확인합니다.
- API 키를 코드에 설정하거나 기존 설정을 준비하고 run_windows.bat를 더블클릭합니다.
- 도우미가 Python 가상환경과 필요한 패키지를 준비합니다.
- 키가 모두 준비되어 있으면 다시 입력받지 않고 앱을 실행합니다.
- 키가 부족하면 터미널에서 한 번 설정할 수 있습니다.

Python 3.11 이상이 필요합니다. 개발 검사에는 Python 3.12를 사용했습니다.
Python 설치: https://www.python.org/downloads/windows/

직접 터미널로 설치하려면 app.py가 있는 폴더에서 다음 순서로 실행합니다.
.venv가 없을 때만:
py -3 -m venv .venv

처음 설치하거나 누락된 패키지가 있을 때:
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt

앱 실행:
.\.venv\Scripts\python.exe -m streamlit run .\app.py

py를 찾지 못하지만 Python이 설치되어 있다면 python -m venv .venv를 사용할 수 있습니다.
PowerShell에서 가상환경 활성화나 실행 정책 변경은 필요하지 않습니다.
브라우저가 자동으로 열리지 않으면 터미널에 표시된 Local URL을 엽니다.
일반적인 주소는 http://localhost:8501 입니다. 실제로 표시된 주소를 사용하세요.
앱을 사용하는 동안 터미널은 열어 두고, 종료할 때는 Ctrl+C를 누릅니다.


3. API 키 입력 위치와 자동 사용

app.py 맨 위의 두 줄에 본인의 키를 넣을 수 있습니다.

ADMIN_API_KEY = ""
KAKAO_REST_API_KEY = ""

따옴표 안을 다음 형식으로 채웁니다. 아래 문구는 실제 키가 아닌 입력 위치 설명입니다.

ADMIN_API_KEY = "본인의 행정안전부 Decoding 키 전체"
KAKAO_REST_API_KEY = "본인의 카카오 REST API 키 전체"

키 앞의 여는 큰따옴표와 키 뒤의 닫는 큰따옴표를 모두 유지하세요.
Enter로 키 중간에 줄을 나누지 말고 한 줄에 넣은 뒤 Ctrl+S로 저장합니다.
자동 줄바꿈으로 화면에서 길게 보이는 것과 실제 Enter 줄바꿈은 다릅니다.
SyntaxError: unterminated string literal이 나오면 먼저 닫는 큰따옴표가 빠졌는지 확인하세요.

행정안전부: 행정표준코드_법정동코드 API의 일반 인증키(Decoding)를 사용합니다.
카카오: REST API 키와 Local API 이용 권한이 필요합니다.
키가 준비되면 사이트 방문자가 따로 키를 입력할 필요가 없습니다.
설정된 키가 있다는 안내와 실제 API 인증 성공은 다르므로 화면의 조회 결과를 확인하세요.

기존 설정 방식도 유지합니다.
적용 순서: 코드 직접 입력 → Streamlit Secrets → 환경변수 → 로컬 설정 도우미 JSON.
- Streamlit Secrets: 프로젝트 .streamlit/secrets.toml 또는 배포 앱의 Secrets 설정.
- 같은 이름의 값은 프로젝트 Secrets가 사용자 공통 Secrets보다 우선합니다.
- 환경변수: 운영체제나 배포 서버에 ADMIN_API_KEY, KAKAO_REST_API_KEY 이름으로 등록한 값.
- 로컬 도우미: setup_api_keys.bat 또는 configure_keys.py가 저장한 .streamlit/villageon_keys.json.
앱이 .env 파일을 자동으로 읽는 기능은 없습니다.

설정 도우미는 코드의 두 문자열을 앱 실행 없이 읽어 확인합니다.
코드에 두 키가 있으면 다시 입력받거나 JSON으로 복사하지 않습니다.
코드에 한 키만 있으면 다른 키는 기존 설정 또는 터미널 입력으로 준비합니다.
터미널에서 키를 붙여넣을 때 글자나 별표가 보이지 않는 것이 정상입니다.
이미 도우미에 저장된 키는 빈 Enter로 유지할 수 있습니다.

공개 GitHub에는 실제 키를 넣은 app.py를 올리지 마세요.
공개 배포에서는 코드의 두 값은 빈칸으로 두고 Streamlit Settings → Secrets에 등록합니다.
실제 키가 있는 secrets.toml, villageon_keys.json, .env와 .venv 폴더도 업로드하지 않습니다.
오류 내용을 다른 사람에게 보낼 때는 실제 키 부분을 가려 주세요.


4. 이번 화면 구성

지역 소비 시뮬레이터를 지역 관리자·상인회와 개별 상인이 사용할 수 있는 두 가지 계산으로 구성했습니다.
입력은 쉬운 질문으로, 결과는 큰 금액과 간단한 표로 보여 줍니다. 그래프와 지출 편집표는 제거했습니다.
지역 브리핑 제거, 큰 메뉴와 버튼, 콘텐츠의 전체 분류 제거, AI의 동일 숙소 일정은 유지합니다.

메뉴는 다음 네 개입니다.

① 콘텐츠 탐색
② 지역 소비 시뮬레이터
③ AI 추천
④ 예산 여행 코스

지역 브리핑은 제거했습니다. 예전 브리핑의 지역 점수, 장소 수 차트, 레이더는 표시하지 않습니다.
숨은 명소와 발표 모드도 계속 제거된 상태입니다.
사이드바 메뉴, 콘텐츠 선택, 검색·계산·추천·다운로드 버튼의 누를 수 있는 영역과 글씨를 키웠습니다.
작은 화면에서는 선택 항목이 줄을 바꿔 배치되도록 했습니다.


5. 콘텐츠 탐색

'전체' 항목을 제거했습니다. 다음 종류 중에서 고릅니다.
맛집 / 카페 / 관광지 / 숙박 / 학교 / 공원 / 문화 / 체험

종류와 검색어를 고른 뒤 [검색]을 누릅니다.
예를 들어 학교를 찾으려면 먼저 [학교]를 선택하세요.
다른 종류를 찾으려면 위 콘텐츠 버튼을 바꾸면 됩니다.

결과 수 옆에 '카카오 정확도순 검색 결과'를 표시합니다.
한 페이지 15건씩 최대 3페이지를 조회하고 같은 장소 ID를 합쳐 검색당 최대 45곳을 보여 줍니다.
실제 검색 결과가 적거나 중복·부분 실패가 있으면 45곳보다 적게 표시될 수 있습니다.
45는 검색 목록의 수집 상한이며 해당 지역 전체 업소 수가 아닙니다.
학교나 식당이 같은 이름을 쓰더라도 장소 ID가 다르면 다른 장소로 유지합니다.

거리순을 선택한 결과에는 '카카오 거리순 검색 결과'라고 표시합니다.
거리 기준은 선택 지역의 확인된 좌표이며, 휴대폰 현재 위치나 실제 도로 이동 거리가 아닙니다.
전체 지역명과 검색어를 함께 사용하고 좌표가 확인되면 기준점 반경 20km를 적용합니다.
반경은 행정구역 경계와 다르므로 인접 지역이 포함될 수 있습니다.
좌표가 확인되지 않으면 전체 지역명으로 검색합니다.

카카오 Local API가 별점과 평가 수를 제공하지 않아 별점순 정렬은 지원하지 않습니다.
각 장소의 [카카오맵에서 상세·후기 보기]에서 확인할 수 있습니다.
인증 실패나 부분 조회는 정상 검색 결과 0건과 구분해서 안내합니다.


6. 지역 관리자·상인을 위한 지역 소비 시뮬레이터

선택한 지역에서 방문객이 늘어났을 때 발생할 소비와 가게의 매출을 가정으로 계산합니다.
[지역 전체 소비 효과]와 [우리 가게 예상 매출] 중에서 보고 싶은 대상을 고릅니다.
두 모드는 분석 기간 이름과 그 기간의 추가 방문객 수를 함께 사용합니다.
추가 방문객은 여행 일행의 인원이 아니라 행사·홍보 등으로 더 방문할 것으로 가정한 인원입니다.

먼저 [1개월], [가을 축제 기간] 같은 기간 이름과 추가 방문객 수를 입력합니다.
기간 이름을 1개월에서 1년으로 바꿔도 방문객 수나 비용을 자동으로 12배 하지 않습니다.
모든 기본값은 입력 예시입니다. 선택 지역의 실제 매출·공식 통계·실제 가격·AI 예측 결과가 아닙니다.

A. 지역 전체 소비 효과 — 지역 담당자·상인회

기본 화면에서 한 사람이 당일 방문에 쓸 금액과 그중 선택 지역 안에서 쓸 비율을 입력합니다.
기본 예시는 추가 방문객 1,000명, 1인 당일 지출 50,000원, 지역 안에서 쓰는 비율 80%입니다.
숙박 비율은 기본 0%이므로 이 조건에서는 모두 당일 방문으로 계산합니다.
예상 지역 내 소비액 = 1,000명 × 50,000원 × 80% = 40,000,000원.

숙박 여행객도 있다면 접힌 숙박 설정에서 다음 값을 조정합니다.
- 방문객 중 숙박 여행을 하는 비율.
- 숙박 여행객의 평균 숙박일.
- 숙박객 한 사람이 하루에 쓸 돈: 숙박비 제외.
- 숙박비: 한 사람의 1박 금액.

숙박 비율 30%는 추가 방문객 100명 중 30명이 숙박 여행, 70명이 당일 여행을 한다는 가정입니다.
숙박 인원은 0.5명 이상을 올려 정수로 반올림합니다.
당일객의 일일 지출은 1일, 숙박객의 일일 지출은 평균 숙박일+1일에 적용합니다.
숙박비는 숙박 횟수만 곱합니다. 2박 3일이면 일일 지출은 3일, 숙박비는 2박입니다.
같은 사람을 당일객과 숙박객 양쪽에 더하지 않습니다.
객실 1박 100,000원을 두 사람이 나눠 내면 1인 1박 숙박비는 50,000원입니다.

지역 안에서 쓰는 비율은 일반 지출과 숙박비 모두에 동일하게 한 번 적용합니다.
숙박 여행객의 모든 숙소가 선택 지역 안에 있다고 확정하는 계산은 아닙니다.
이 비율은 선택 지역에서 이용·결제한다고 가정하는 몫이며 순이익률이나 지역에 남는 이익률이 아닙니다.

업종별 나눔 비율은 접힌 조정 영역에서 변경할 수 있습니다.
기본 예시는 식비 40%, 카페·간식 12%, 입장·체험 20%, 현지 교통 8%, 쇼핑·기타 20%입니다.
다섯 비율의 합은 100%여야 합니다. 실제 지역 업종별 매출 비율을 조회한 값이 아닙니다.
이 비율은 숙박비를 제외한 당일객·숙박객의 일일 지출을 나누는 데 사용합니다. 숙박비는 별도 항목입니다.
원 단위로 배분한 항목의 합계는 입력한 일일 금액과 맞춥니다.

결과는 지역 내 예상 추가 소비액, 추가 방문객, 1인 평균 지역 소비와 업종별 소비액 표로 보여 줍니다.
그래프나 직접 편집하는 지출 표는 없습니다. 지역 밖 지출과 상세 계산은 접힌 설명에서 확인합니다.

B. 우리 가게 예상 매출 — 개별 상인

가게 이름은 선택 입력입니다. 추가 방문객 중 우리 가게에서 구매할 비율과 고객 1명의 평균 구매 금액을 입력합니다.
기본 예시: 방문객 1,000명 × 구매 비율 3% = 추가 고객 30명.
예상 추가 매출 = 30명 × 평균 구매 금액 20,000원 = 600,000원.

예상 고객 수는 0.5명 이상을 올려 정수로 반올림한 뒤 매출을 계산합니다.
한 사람당 한 번 구매하는 조건이며, 구매 비율과 구매 금액은 상인이 입력한 가정입니다.
매출은 비용을 빼기 전 금액입니다. 지역 전체 소비액을 가게 수로 똑같이 나누지 않습니다.
가게의 예상 추가 매출을 지역 전체 예상 소비액에 다시 더해서 합산하지 않습니다.

C. 계산 버튼과 결과 확인

입력한 뒤 화면의 계산 버튼을 눌러야 결과가 갱신됩니다. 값을 바꿨으면 다시 계산해 주세요.
결과에는 마지막으로 제출한 조건을 표시합니다. 선택 지역과 계산 대상에 맞는 결과만 표시합니다.
방문객이 0명이면 지역 소비액과 상인 매출도 0원입니다. 구매 비율 0%이면 추가 고객과 매출이 0입니다.
상세 계산, 방문객을 80%·100%·120%로 바꾼 가정 비교, CSV 다운로드는 접힌 영역에서 확인합니다.
비교 표는 다른 조건을 유지한 계산 예시이며 실제 전망이나 발생 확률을 뜻하지 않습니다.
CSV에는 마지막으로 계산한 입력 조건과 결과를 함께 기록합니다.


7. AI 추천: 후보 목록, 같은 숙소, 날짜별 경로

AI 추천 화면 안에서 여행 관심사를 선택합니다.
선택 관심사에 맞는 분야별 후보를 최대 45곳씩 볼 수 있습니다.
예: 맛집 관심사는 맛집·카페, 자연 관심사는 공원·관광지 후보와 연결됩니다.
목록 옆에 '45/45곳 · 카카오 정확도순 검색 결과'처럼 수와 정렬 기준을 표시합니다.
검색된 수가 더 적으면 실제 확인한 수만 표시합니다.
각 분야의 API 검색 순서를 유지하며 서로 다른 분야를 합친 통합 정확도 순위로 표현하지 않습니다.

시간표는 후보에서 관심사와 여행 기간에 맞는 장소를 고릅니다.
후보 45곳을 하루 일정에 모두 넣는 방식은 아닙니다.

숙박 여행은 여행 전체에서 숙소 한 곳을 골라 같은 곳을 이용합니다.
- 당일치기: 숙박 일정 없음.
- 1박 2일: 1일차에 숙박하고 2일차 아침 같은 숙소에서 체크아웃·출발.
- 2박 3일: 1일차와 2일차 밤에 같은 숙소를 이용하고 3일차 아침 체크아웃·출발.
마지막 날 밤에 숙박을 한 번 더 추가하지 않습니다.
같은 숙소에서의 연박 예약 가능 여부와 요금·실제 체크인/체크아웃 시각은 직접 확인해야 합니다.
숙소 검색 결과가 없으면 임의의 숙소를 만들지 않고 직접 정해야 한다고 안내합니다.

날짜별 지도에는 시간표와 같은 순서 번호를 표시하고 실제 장소 좌표를 직선으로 연결합니다.
2일차부터는 같은 숙소에서 출발하는 순서도 표시합니다.
같은 날 숙소 출발과 귀환이 같은 위치에 겹치면 마커에 해당 순번을 함께 표시합니다.
지도 선은 방문 순서의 개요이며 도로 길찾기 경로나 실측 이동시간이 아닙니다.
좌표가 없는 일정은 표에 남기고 지도에서는 제외하며, 그 일정을 건너뛰어 선을 연결하지 않습니다.
표의 시각은 예시이므로 영업시간과 실제 이동시간은 방문 전에 확인하세요.


8. 예산 여행 코스와 지역 선택

예산 여행 코스는 일행 전체의 총예산을 기준으로 교통·식사·숙박·활동비 등을 계산합니다.
화면에 표시된 인원·객실·1인 금액의 단위를 확인해서 입력하세요.
가격과 이동시간은 계획을 위한 가정이며 실시간 판매 요금이나 예약 가능 여부를 보장하지 않습니다.

전국 지역 선택과 무작위 [지역 추천] 버튼은 유지했습니다.
시·도 → 시·군·구 → 읍·면·동은 행정안전부 법정동 목록을 기준으로 연결합니다.
일부 명칭은 주민센터의 행정동 이름과 다를 수 있습니다.
시뮬레이터의 분석 기간과 숙박 가정은 해당 화면에서, AI 추천과 예산 코스의 여행 기간은 사이드바에서 고릅니다.


9. 오류 확인과 검증 범위

No module named streamlit:
같은 앱 폴더에서 .\.venv\Scripts\python.exe -m pip install -r .\requirements.txt를 실행합니다.

File does not exist: app.py:
파일 이름과 실제 폴더를 확인하고 그 폴더로 cd 이동한 뒤 실행합니다.

SyntaxError: unterminated string literal:
키 앞뒤 큰따옴표를 확인하고 실제 줄바꿈 없이 한 줄로 넣습니다. 오류를 공유할 때는 키를 가립니다.

korea_administrative_district 오류:
이번 코드는 해당 모듈을 사용하지 않습니다. 이전 app.py가 실행 중인지 확인하세요.

예전 지역 브리핑·'전체' 버튼이 보일 때:
실행 중인 서버를 Ctrl+C로 종료하고 새 파일로 다시 실행합니다.
배포 앱이라면 연결된 GitHub 저장소의 Main file path에 있는 파일도 교체하고 Commit해야 합니다.
로컬 파일을 다운로드하는 것만으로 이미 배포된 사이트가 바뀌지는 않습니다.

API 오류:
행정안전부 활용 신청 승인과 Decoding 키, 카카오 REST API 키와 Local API 권한,
호출 한도와 인터넷 연결을 확인합니다. 코드에 넣은 값이 다른 설정보다 우선합니다.

설치 목록은 requirements.txt를 사용합니다.
Streamlit / Requests / Pandas / Folium / Streamlit-Folium을 사용합니다.
그래프를 제거하면서 Plotly 의존성도 제거했습니다. 이미 설치된 Plotly를 따로 삭제할 필요는 없습니다.
지역 브리핑과 시뮬레이터의 그래프는 표시하지 않으며 기존 여행 지도는 유지합니다.

검증 범위는 Python 문법과 모의 데이터 기반 계산·화면 검사입니다.
실제 Windows나 휴대폰에서 직접 조작하거나 사용자의 유효한 API 키로 인증한 검사는 아닙니다.
